artifacts go where this doc says, or they get cleaned up at the next maintenance pass.

## 2. The rules

### R1. One source of truth per artifact class.

| Class | Path | Why |
|---|---|---|
| Current plan | `planning/PLAN-2026-07-28-v3.2.md` | Single, dated, versioned |
| Schema | `intake-data/schema.json` | Single file |
| Template | `concept-briefs/TEMPLATE.md` | Single file |
| Design doc | `DESIGN.md` (root) | Single file |
| README | `README.md` (root) | Single file |
| Structure policy | `docs/STRUCTURE-POLICY.md` | This file |

When you revise the plan: the old one moves to `planning/archive/YYYY-MM-DD/`. The new
one replaces `planning/PLAN-YYYY-MM-DD-vN.M.md`. Never both at root.

### R2. REPORTs and session notes go in `planning/YYYY-MM-DD/`.

A "REPORT" or session note is anything ending in `-REPORT.md`, `-NOTES.md`, or named
`REPORT-*.md`. They go in `planning/YYYY-MM-DD/`. **Never at project root.** The 3
REPORTs that were at root on 2026-07-28 are now at `planning/2026-07-28/`.

### R3. Research sandboxes are dated dirs inside `planning/`.

Pattern: `planning/<topic>-YYYY-MM-DD/` (e.g. `audio-quality-2026-07-30`). Each
sandbox is self-contained: it has its own scripts, data, and a `report.md`. When the
research is done, the dir stays where it is — it's not moved to `archive/` unless
the data is no longer useful.

### R4. Music test sandboxes go in `music/archive/test-YYYY-MM-DD/`.

Music matrix sandboxes are large (200+ MB of mp3/wav + spectrograms). They go in
`music/archive/test-YYYY-MM-DD/` so they don't pollute `music/<album>/`. The
archive is gitignored-by-default but kept on disk for reference.

### R5. Prototypes live in `site/prototypes/<index-or-name>/`.

One folder per prototype. The folder contains `index.html` and optional `.placeholder`.
Screenshots from smoke tests go in `site/prototypes/screenshots/`, **not** in the
prototype's own folder.

### R6. Don't commit the noise.

The `.gitignore` blocks `__pycache__/`, `.od-skills/`, `.placeholder` files,
`*.pyc`, OS junk. If you find yourself wanting to commit a file that the
`.gitignore` is blocking, ask "is this a build artifact?" — if yes, don't commit it.

### R7. Mirrors are byte-verified.

`~/OneDrive/Hermes/Agents/planning/album-studio/` is the cross-device mirror.
It must byte-match the project for any source file. After any write to the project,
run the mirror loop:

```bash
PROJ='C:\Users\lion_\Documents\Projects\album-studio'
ONE='C:\Users\lion_\OneDrive\Hermes\Agents\planning\album-studio'
cd "$PROJ" && find . -type f -not -path "./.git/*" -not -path "./.od-skills/*" \
    -not -path "./music/archive/*" -not -path "./site/prototypes/screenshots/*" \
    -not -path "./tests/screenshots/*" | while read f; do
  [ ! -f "$ONE/$f" ] || [ "$(md5sum "$PROJ/$f" | cut -c1-32)" != "$(md5sum "$ONE/$f" | cut -c1-32)" ] \
    && mkdir -p "$(dirname "$ONE/$f")" && cp "$PROJ/$f" "$ONE/$f"
done
```

## 3. The antipatterns this prevents

The cleanup of 2026-08-01 was triggered by these antipatterns. Don't do them.

### ❌ AP1. Multiple PLAN-* files at the project root or planning/ root

We had 4: `v1`, `v3`, `v3.1`, `v3.2`. Only one was the canonical plan. The rest
are in `planning/archive/2026-07-28/` now.

**Why it happens:** the plan evolved during a single day and we never consolidated.
**Prevention:** when a new plan version ships, `mv` the old one to `planning/archive/<date>/`.

### ❌ AP2. REPORTs scattered at project root

We had 3 REPORTs at project root. They're historical, not current.

**Prevention:** R2. They're date-folderized inside `planning/`.

### ❌ AP3. Sandboxes without a home

`music-test-2026-07-29/` lived at the OneDrive top-level with no canonical home.
Now it's `music/archive/test-2026-07-29/`.

**Prevention:** R4. Music test sandboxes have a known canonical home.

### ❌ AP4. Orphan snapshot dirs

`album-studio-2026-07-28-hybrids/`, `…-templates-v2/`, `…-GO-ALL/` — three
full-project snapshots from earlier in the day. Now in
`~/OneDrive/Hermes/Agents/planning/album-studio-archive-2026-07-28/`.

**Why they accumulated:** iterative GO-ALL/HYBRIDS/TEMPLATES-V2 sessions, each
copying the whole project. The REPORTs reference them as evidence of past states.
**Prevention:** when a session creates a snapshot, give it a name that includes the
session's purpose (e.g. `snapshot-2026-07-28-1430-hybrids/`) and **delete the
predecessor when the next session supersedes it**. If the predecessor is referenced
in a report, move it under `…/planning/album-studio-archive-YYYY-MM-DD/` instead.

### ❌ AP5. Mirrors out of sync with project

The OneDrive mirror had 36 missing source files and 4 misplaced PLANs.

**Prevention:** R7. The byte-verify mirror loop is the canonical mechanism.

### ❌ AP6. Nested mirror artifacts

`planning/audio-quality-2026-07-30/audio-quality-2026-07-30/` contained 39
duplicate + unique files from an earlier incomplete mirror. This kind of nested
dir is a strong signal of a botched `mkdir && cp` script.

**Prevention:** flat mirrors only. If you copy a dir into a mirror, verify the
mirror's parent doesn't already have a sibling of the same name.

## 4. Maintenance checklist

Run this every quarter or after any major session:

- [ ] `find . -name "REPORT-*.md" -not -path "./planning/*"` — should be empty
- [ ] `find . -maxdepth 1 -name "PLAN-*.md"` — should be at most one file (current plan)
- [ ] `find . -maxdepth 1 -name "*.md" -not -name "README.md" -not -name "DESIGN.md"` — should be empty
- [ ] Run the mirror byte-verify loop (R7); 0 mismatches
- [ ] `git status` — should show clean working tree or only intentional changes
- [ ] No `__pycache__/` visible to `git status` (means `.gitignore` is working)

## 5. When you change this policy

1. Edit this file.
2. Run the mirror byte-verify loop to update the OneDrive copy.
3. Note the change in the plan v3.2 changelog or its successor.

## Long-term fixes (Day 3 bugfixes)

### db/connection.py — per-thread connections (CRITICAL)
**Root cause:** SQLite connections are NOT safe to share across threads. The original code used `check_same_thread=False` and a module-level dict cache — that worked for Day 2 (single-threaded CLI) but fails in Day 3 (async ASGI server with worker threads).

**Fix:** `threading.local()` keyed cache. Each OS thread that calls `open_db()` gets its own connection. `close_db()` actually closes the handle (no connection leak). `check_same_thread=True` (the safe default).

**Impact:** eliminates cross-thread sqlite3 corruption, which was the root cause of all Day 2 test failures with the async test client.

### build/serve.py — asyncio.to_thread() for sync DB calls
**Root cause:** Quart handlers are `async def` but `open_db()` / `db.query.*` are sync sqlite3 calls. Mixing sync and async without offloading blocks the event loop.

**Fix:** All sync DB calls in async handlers use `asyncio.to_thread(fn, *args)` (Python 3.9+ standard). No Quart dependency, no run_in_threadpool.

**Impact:** establishes the pattern for ALL Day 4+ handlers. Every `handlers/*.py` route that touches the database must follow this pattern.

### build/serve.py — hypercorn as ASGI server (replaced broken app.run())
**Root cause:** Quart's `app.run()` is a dev server (single-threaded, blocking). hypercorn is the proper ASGI server (installed as Quart's dependency).

**Fix:** `hypercorn.config.Config.bind = ["127.0.0.1:8765"]` + `hypercorn.asyncio.serve(app, config)`. Falls back to `app.run()` only if hypercorn is unavailable (shouldn't happen — it's a Quart dep).

**Impact:** proper concurrent request handling for production; test client uses in-process ASGI (no subprocess race).

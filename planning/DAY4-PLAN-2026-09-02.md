## Pattern (from Day 3)

- All handlers `async def`
- All DB calls via `asyncio.to_thread(fn, *args)`
- Each handler module exports `register_routes(app)` 
- `serve.py` calls both modules' `register_routes(app)`
- Tests use `IsolatedAsyncioTestCase` + Quart test_client + `ALBUM_STUDIO_DB_PATH` tempdb (test_serve.py pattern)

## Test plan

For each endpoint, at least one happy-path + one error-path:
- 200/201 for happy
- 404 for missing id
- 409/422 for state machine violations (e.g., resume when already active, complete when done, archive when not exist)
- 400 for missing required fields
- Concurrent `POST /api/sessions` race test (regression-pinning)

## UI plan (site/albums.html)

Single page, three sections:
1. **Albums grid** — list of albums (cover thumb, title, artist, status pill, runtime)
2. **Sessions panel** — show open sessions (max 3), with pause/resume/complete buttons
3. **Create album modal** — form with title, artist_id (select), release_date, runtime_min

Pure JS — fetch from `/api/albums`, `/api/sessions`. No build step. Mixtape '85 design tokens (CSS vars).

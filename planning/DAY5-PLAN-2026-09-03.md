# Events API contract

`/api/albums/{id}/events` +
- POST /api/events (create)
- GET /api/events?album=... (list)
- GET /api/events/{id} (get one)
- POST /api/events/{id}/pause
- POST /api/events/{id}/resume
- POST /api/events/{id}/complete

With the same pattern as Day 1-4 sessions: open -> pause/resume/complete, with current_layer + session_phase, timeline events.

# Decisions API contract

`/api/albums/{id}/decisions` +
- POST /api/decisions (create)
- GET /api/decisions?album=... (list)
- GET /api/decisions/{id} (get one)
- POST /api/decisions/{id}/approve
- POST /api/decisions/{id}/reject

Similar schema to Events (id, album_id, title, description, status, created_at, updated_at).

## Architecture

Pattern from Day 3:
- All handlers `async def`
- All sync DB calls go through `_run(fn, *args)` which wraps `asyncio.to_thread(fn, ...)`
- Each request: open fresh connection → call fn → close connection
  (`close_db()` in `finally` of `_wrapped()` so the per-thread cache is reset)
- Quart Blueprints let each handler module own its routes

## Key bug fixes during Day 4

### 1. `db/connection.py` — per-thread cache as module-level dict

`threading.local()` is per-thread by design, so `close_all()` couldn't reach into another thread's cache to clear it. Result: after the previous test class's connections closed, the next test class's worker threads re-used the stale "closed" connection from their cached `_thread_local.connections` dict.

**Fix:** replaced `threading.local()` with a module-level dict `_thread_local: dict[int, dict]` keyed on `threading.get_ident()`. `close_all()` now iterates `_thread_registry` and clears every thread's cache entry.

### 2. `db/connection.py` — `default_db_path()` reads env at call time

The original `DEFAULT_DB_PATH = Path(_OVERRIDE).resolve()` was computed at module-import time. Tests that toggled `ALBUM_STUDIO_DB_PATH` mid-process and re-imported `db.*` would freeze on stale function references because `db.connection.open_db.__globals__` still pointed at the OLD module's `DEFAULT_DB_PATH`.

**Fix:** `DEFAULT_DB_PATH = default_db_path()` (call time). Even function references frozen at the FIRST import now resolve the current env via `default_db_path()`.

### 3. `build/serve.py` — local imports inside handlers

Top-level `from db import open_db, run_migrations, close_db, DEFAULT_DB_PATH` froze references to the FIRST-import's `db.connection.open_db` function. After test isolation re-imports `db.*`, the cached function reference still pointed at the OLD module.

**Fix:** handlers do `from db.connection import open_db, close_db` INSIDE the route closure. The function lookup happens per-request, so it always uses the current `sys.modules["db.connection"]`.

### 4. Test isolation — also drop `build.*` modules

When test isolation dropped `db.*` from `sys.modules` to force a fresh import, it didn't drop `build.*`. So `build.serve.py` still had cached `from db.queries import global_status` references. The OLD `global_status` opened connections that were registered in the OLD `_thread_registry`, never closed by the NEW module's `close_all()`.

**Fix:** `_isolate_tempdb()` in test_handlers_*.py and test_serve.py/test_cli.py now drops `build.*` too.
